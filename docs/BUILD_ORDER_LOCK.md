# AuditFlow Build Order Lock

Core correctness must come before AI, advanced infrastructure, and enterprise expansion.

## Core product correctness

1. Specification lock and ADRs.
2. Project skeleton, PostgreSQL, Prisma migrations, request IDs, and standardized errors.
3. Opaque sessions, CSRF, membership context, RBAC, and audit events.
4. Framework families, framework versions, controls, and evidence requirements.
5. Secure staged upload, immutable evidence versions, review, and download authorization.
6. Manual mappings and deterministic readiness calculation.
7. Tasks, comments, dashboard metrics, and basic reports.
8. Frontend completion states, accessibility, cross-tenant/RBAC tests.
9. Deployment, backups, observability, and release controls.

## Add after the core workflow is reliable

- Text extraction.
- AI summaries and suggested mappings.
- Background jobs.
- Notifications and reminders.
- PDF reports.
- Advanced search.
- Evidence expiry alerts.

## Enterprise expansion

- SSO.
- Advanced RBAC.
- Integrations.
- Automated evidence collection.
- Expanded auditor portal workflows.
- Additional framework templates.

## Stop-work rule

If a change violates the locked specification, stop feature work and create a corrective task. Do not hide unresolved defects behind documentation.
